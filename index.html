Control de versiones

Definición

Un sistema de control de versiones (VCS) registra los cambios hechos a los archivos de un proyecto a lo largo del tiempo. Permite volver a versiones anteriores, saber quién cambió qué y cuándo, y trabajar en equipo sin pisarse el trabajo. Es la base de la gestión de la configuración del software.

Conceptos clave

  • Repositorio: carpeta del proyecto junto con todo su historial.
  • Commit: “foto” de los cambios con autor, fecha y mensaje.
  • Rama (branch): línea de desarrollo paralela, por ejemplo una función nueva.
  • Merge: unión de una rama con otra; si dos cambios chocan aparece un conflicto que se resuelve a mano.
  • Tag: etiqueta que marca una versión estable (v1.0).
  • Clone, push y pull: copiar un repositorio, enviar cambios al remoto y traer los de otros.

Tipos de sistemas

TipoCómo funcionaVentajasDesventajas
Local (RCS)Guarda versiones en una base de datos en el mismo equipo.Simple, sin red.Sin colaboración; un fallo de disco pierde todo.
Centralizado (SVN, CVS)Un servidor central guarda el historial; cada usuario descarga una copia de trabajo.Control de permisos fácil, flujo sencillo.Punto único de falla; requiere conexión para casi todo.
Distribuido (Git, Mercurial)Cada usuario clona el repositorio completo con todo su historial.Trabajo sin conexión, ramas rápidas, respaldo natural.Curva de aprendizaje; historiales grandes pesan más.

Funcionamiento (modelo distribuido)

En Git cada archivo pasa por tres estados: modificado (cambiado en tu carpeta), preparado (git add, listo para el próximo commit) y confirmado (git commit, guardado en el historial). Después se sincroniza con el remoto.

Servicios como GitHub, GitLab y Bitbucket alojan repositorios remotos y añaden pull requests y revisión de código.

Persistencia y acceso a datos

Definición y características

La persistencia es la capacidad de una aplicación de conservar datos después de cerrarse o reiniciarse el dispositivo. Sus características principales: durabilidad, consistencia, rapidez de acceso, seguridad y capacidad de recuperación.

Formas de persistencia en móviles

FormaDescripciónDatos que almacena
ArchivosAlmacenamiento interno o externo; también preferencias clave-valor (SharedPreferences / DataStore).Configuraciones, texto, JSON, imágenes, audio, caché.
Base de datos localSQLite integrado en el dispositivo (Room, Core Data, Realm).Datos estructurados y relacionales: usuarios, productos, historial.
Base de datos remotaServidor accesible mediante servicios web (REST/JSON) o servicios como Firebase.Datos compartidos entre usuarios y dispositivos; respaldos.

Mecanismos de control de acceso

  • Biblioteca de clases: APIs del sistema (File, SharedPreferences) que encapsulan el acceso al medio.
  • Clases de SQLite: SQLiteOpenHelper crea y actualiza la base; SQLiteDatabase ejecuta consultas.
  • Mapeo objeto-relacional (ORM): convierte tablas en clases (Room, GRDB, Core Data), evitando escribir SQL a mano. Android recomienda Room en lugar de usar SQLite directamente.

Autenticación y consumo de servicios web

  1. El usuario envía credenciales a la API por HTTPS.
  2. El servidor las valida y devuelve un token (por ejemplo JWT).
  3. La app guarda el token de forma segura (Keystore / Keychain).
  4. Cada petición posterior incluye el token en el encabezado Authorization.
  5. La app procesa la respuesta JSON y la muestra o guarda localmente.

Ejemplo (Kotlin con Room)

@Entity data class Alumno(@PrimaryKey val id: Int, val nombre: String)

@Dao interface AlumnoDao {
    @Query("SELECT * FROM Alumno") fun todos(): List<Alumno>
    @Insert fun insertar(a: Alumno)
}

Room 3.0 usa el paquete androidx.room3, exige KSP y basa sus operaciones en corrutinas; las versiones 2.x usan androidx.room. Revisa la versión que pide tu proyecto en la documentación oficial.

Gestión de sensores

Definición: un sensor es un componente de hardware que mide una magnitud física (movimiento, luz, posición) y la convierte en datos que la app puede leer.

Tipos de sensores

CategoríaSensoresUso típico
MovimientoAcelerómetro, giroscopioGirar la pantalla, contar pasos, juegos.
PosiciónGPS, magnetómetro, proximidadMapas, brújula, apagar la pantalla en llamadas.
AmbienteLuz, barómetro, temperatura, humedadBrillo automático, altitud.
Biometría y capturaHuella, rostro, cámara, micrófonoAutenticación, fotos, voz.

Proceso de gestión

  1. Habilitación: declarar permisos en el manifiesto y pedirlos en tiempo de ejecución; comprobar que el sensor existe en el dispositivo.
  2. Obtención: registrar un listener con el administrador de sensores y recibir las lecturas.
  3. Procesamiento: filtrar el ruido, convertir unidades y reaccionar (girar la pantalla, contar pasos).
  4. Liberación: anular el registro al pausar la app para ahorrar batería.
val sm = getSystemService(SENSOR_SERVICE) as SensorManager
val acel = sm.getDefaultSensor(Sensor.TYPE_ACCELEROMETER)
sm.registerListener(this, acel, SensorManager.SENSOR_DELAY_NORMAL)
override fun onSensorChanged(e: SensorEvent) { val x = e.values[0] }
override fun onPause() { super.onPause(); sm.unregisterListener(this) }
Norma relacionada: ISO/IEC 25010:2023: el uso de sensores afecta la eficiencia de desempeño (batería y recursos) y la seguridad (privacidad de ubicación y biometría).

Uso de recursos multimedia

Definición: son los elementos de imagen, sonido, video y animación que enriquecen la interfaz y la experiencia del usuario.

Tipos de recursos

TipoFormatos comunesConsejo
ImágenesPNG, JPG, WebP, SVG / VectorDrawableUsa vectores para íconos y WebP para fotos ligeras.
AudioMP3, OGG, WAVWAV o OGG corto para efectos; MP3 para música.
VideoMP4, WebM, streamingLibera el reproductor al pausar la app.
AnimacionesAnimaciones de propiedades, Lottie, GIFEvita animaciones largas que gasten batería.
Elementos visuales dinámicosGráficos, mapas, vistas personalizadasActualiza solo la parte que cambia.

Componentes de software

  • ExoPlayer (Jetpack Media3) y MediaPlayer para audio y video.
  • ImageView y librerías como Glide o Coil para mostrar imágenes.
  • SoundPool para efectos cortos; MediaRecorder y CameraX para capturar.

Práctica guiada oficial: Media streaming with ExoPlayer (codelab de Android). Enseña a crear el reproductor y a ligarlo al ciclo de vida de la actividad.

Norma relacionada: ISO/IEC 25010:2023: la calidad de la experiencia multimedia se evalúa en capacidad de interacción y eficiencia de desempeño.

Servicios y notificaciones

Definición: los servicios son componentes que ejecutan trabajo sin interfaz visible; las notificaciones son mensajes que la app muestra fuera de su pantalla.

Tareas en segundo plano

Son operaciones que corren sin que el usuario interactúe: sincronizar datos, descargar archivos, reproducir música. Según la documentación de Android, el trabajo es persistente cuando sigue programado tras reiniciar la app o el sistema, y WorkManager es la solución recomendada para ese tipo de trabajo. Puede ser inmediato, de larga duración o diferible (periódico).

Tratamiento de notificaciones

Existen locales (generadas por la app) y push (enviadas desde un servidor, p. ej. Firebase Cloud Messaging). Desde Android 8 se organizan en canales y desde Android 13 se pide permiso al usuario.

Proceso de implementación

  • Proveedor de contenido: clase que extiende ContentProvider, se declara en el manifiesto y expone datos a otras apps por URIs.
  • Tarea en segundo plano: crear un Worker con doWork() y programarlo con WorkManager.
  • Notificación: crear el canal, construir con NotificationCompat.Builder y mostrarla con notify().
class SyncWorker(ctx: Context, p: WorkerParameters) : Worker(ctx, p) {
    override fun doWork(): Result {
        // sincronizar datos aquí
        return Result.success()
    }
}
val req = OneTimeWorkRequestBuilder<SyncWorker>().build()
WorkManager.getInstance(context).enqueue(req)

Depuración y seguridad

Depuración: proceso de encontrar y corregir errores en el código. Seguridad: conjunto de prácticas que protegen los datos y el funcionamiento de la app frente a accesos o usos indebidos.

Herramientas de depuración

HerramientaPara qué sirve
Logcat / Log.d()Mensajes del sistema y de la app.
Depurador con breakpointsPausa la ejecución e inspecciona variables.
ProfilerMide CPU, memoria, red y batería.
Layout InspectorRevisa la jerarquía de vistas.
Database InspectorConsulta y edita la base de datos de la app mientras corre.
Emuladores y ADBPrueban en distintos dispositivos y envían comandos.
Xcode InstrumentsEquivalente de análisis en iOS.

Buenas prácticas de seguridad

  • Usar HTTPS y validar certificados.
  • Guardar secretos en Keystore / Keychain, nunca en el código.
  • Pedir solo los permisos necesarios.
  • Ofuscar el código (R8 / ProGuard) y validar toda entrada del usuario.
  • Integrar la seguridad en todo el ciclo de vida, no solo al final.
